## 3) Locked Decisions In This Phase
- **Architecture decisions**:
  - **Multi-stage build** over single-stage: smaller final image (drops build-essential ~200MB), layer sharing between stages, clean separation of build vs runtime deps.
  - **Each pre-baked model is its own `RUN` layer** to avoid invalidating other layers when requirements.txt changes. large-v3 being ~3GB is particularly sensitive to unnecessary rebuilds.
  - **Env vars not CLI flags for installer secrets**: `NGROK_TOKEN`/`GEMINI_KEYS` never enter bash history. Standard pattern for deployment scripts. Documented in script help + skill markdown.
  - **Sentinel files for resume**: `/workspace/.vt-installer/step-N.done` is the canonical "is this step done" marker. Survives instance restart (on `/workspace` volume if mounted) or a fresh run finds them stale (no sentinel = redo). Simple + reliable.
  - **Inline Python helper for model downloads** via heredoc rather than shipping a separate `.py` file: keeps installer self-contained, easy to paste into Vast.ai Jupyter Terminal. Written to `/tmp/vt-download-models.py`, deleted after use.
  - **Dual tunnels run in parallel** (not serial): both URLs always attempted so if cloudflared rate-limits (~50/hr per IP), ngrok is immediately usable. No waiting to decide which one.
  - **Cloudflared trycloudflare quick tunnel** (not named tunnel): user has no domain, this is zero-setup alternative. Random URL each time but that's acceptable because the user can always pick from the output.
  - **GHCR tags: `latest` + `sha-<7>` + branch name**: standard from `docker/metadata-action`. `latest` for production pull, SHA for rollback, branch for feature branches if added later.
  - **GHCR public flip is one-time manual**: unavoidable since GitHub doesn't expose package visibility via API during creation. Documented in workflow summary + installer skill.
  - **`test_deploy_lint.py` tests read files as text and grep for patterns**: cheap, fast, catches regressions without needing Docker installed locally. 44 tests run in <150ms.
- **Config changes**: none (no runtime config touched)
- **API contract changes**: none
- **Error handling policy**:
  - Installer: `set -euo pipefail` + `trap 'on_error $LINENO $?' ERR` — prints resume command on failure
  - Start script: `set -euo pipefail` + `trap cleanup SIGTERM SIGINT` — kills background processes on Ctrl+C
- **Why these decisions were chosen**:
  - "Multi-stage build" → smaller image pulls faster on Vast.ai
  - "Env vars for secrets" → user locked decision, safer than CLI flags
  - "Dual tunnels" → user locked decision, solves the "Visit Site" pain without requiring Cloudflare account
  - "GHCR public" → free unlimited for public, image contains only open-source code+models (no secrets)

### 7.5 Edge Cases Covered

## 8) Risks, Issues, And Mitigation
- **New risks**:
  - **GHA first build timeout**: `timeout-minutes: 60` set. Large-v3 + torch+cu121 download can be slow. Fallback: workflow_dispatch to manually retry.
  - **GHCR visibility flip**: requires one-time manual GitHub UI action. If forgotten, Vast.ai pulls will fail with auth error. Mitigated by documentation in skill markdown + GHA job summary.
  - **Bash script portability**: scripts assume bash (not sh/dash). Vast.ai uses bash by default — verified by user's previous manual installs.
  - **Inline Python heredoc in installer**: if someone edits the script and introduces unmatched `PYEOF`, the bash parser would consume everything until EOF. Mitigated by `bash -n` syntax check passing.
  - **Windows line endings**: `.gitattributes` already has `text=auto eol=lf` configured. New `.sh` files will have LF on commit. Verified by git status warnings showing "LF → CRLF" (Git is storing LF correctly).
- **Known issues**: none
- **Severity**: low
- **Mitigation in place**:
  - 44 lint tests catch regressions automatically
  - Installer `RESET=1` provides easy recovery path
  - Start script runs both tunnels in parallel so one failure doesn't block the other
  - `set -euo pipefail` in both scripts prevents silent failures
- **Rollback strategy**: `git revert` on the single P6.B commit. Docker image would still need to be manually deleted from GHCR if published, but that's low-impact because it's a separate registry not the runtime code.
